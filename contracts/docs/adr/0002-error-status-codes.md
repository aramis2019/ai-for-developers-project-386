# ADR 0002. Разделение 409 и 422 в ответах на создание бронирования

- **Статус:** принято
- **Дата:** 2026-08-15

## Контекст

`POST /api/bookings` может завершиться неудачей по нескольким причинам:
слот занят другим гостем, `start` не выровнен по сетке, встреча выходит
за окно записи или за рабочие часы, некорректные контактные данные.

Соблазн — отдавать на всё `400` с разными сообщениями.

## Решение

| Ситуация | HTTP | Код |
| --- | --- | --- |
| Слот заняли, пока гость заполнял форму | 409 | `SLOT_ALREADY_BOOKED` |
| `start` не выровнен по шагу сетки | 422 | `SLOT_NOT_ALIGNED` |
| Вне окна 14 суток или в прошлом | 422 | `SLOT_OUT_OF_WINDOW` |
| Не помещается в рабочие часы | 422 | `SLOT_OUTSIDE_WORKING_HOURS` |
| Некорректные контакты | 422 | `VALIDATION_FAILED` |
| Тип события не существует | 404 | `EVENT_TYPE_NOT_FOUND` |
| Тело не разобрано | 400 | `BAD_REQUEST` |

## Обоснование

Это разные ветки поведения клиента, а не разные тексты одной ошибки:

- **409** — состояние сервера изменилось. Ввод гостя был корректен, повтор того же
  запроса не поможет. UI обязан перезапросить слоты и попросить выбрать другое время.
- **422** — ввод некорректен. Перезапрос слотов ничего не изменит, надо чинить данные.
- **404** — ресурс исчез, нужно вернуть гостя на список видов брони.

Различать это по тексту сообщения нельзя: тексты локализуются и переписываются.

## Последствия

- Клиент ветвится по полю `code`, а не по `message`.
- Поле `details` в `ErrorBody` несёт контекст: для `SLOT_ALREADY_BOOKED` — занятый
  интервал, для `VALIDATION_FAILED` — список проблемных полей.
- `ErrorCode` объявлен как открытый union (`string` в списке вариантов), поэтому
  добавление нового кода не является ломающим изменением для клиентов.
