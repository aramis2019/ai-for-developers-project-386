# ADR 0001. Сквозная занятость вместо занятости по типу события

- **Статус:** принято
- **Дата:** 2026-08-15

## Контекст

Гость выбирает тип события и слот. Нужно решить, что считать конфликтом:
пересечение бронирований в пределах одного типа события или по всему календарю.

## Решение

Занятость **сквозная**: никакие два бронирования не пересекаются по времени,
независимо от типа события.

Формально: для любых `A ≠ B` верно `A.end <= B.start || B.end <= A.start`.

## Обоснование

Владелец календаря один и физически не может провести две встречи одновременно.
Занятость по типу события допустила бы двойную запись на один час и сделала бы
страницу предстоящих встреч бессмысленной.

## Последствия

- `GET /api/event-types/{id}/slots` вычитает из сетки **все** брони, а не только
  брони этого типа события.
- Проверка занятости и вставка должны быть атомарны (транзакция + уникальное
  ограничение или блокировка диапазона), иначе гонка двух гостей нарушит инвариант.
- Конфликт возвращается как `409 SLOT_ALREADY_BOOKED` — отдельно от `422`,
  потому что клиенту нужно перезапросить слоты, а не чинить ввод.
