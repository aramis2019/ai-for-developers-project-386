Подготовь релиз репозитория по сценарию из скилла `git-release`.

Аргументы пользователя (могут быть пустыми): $ARGUMENTS

Порядок:

1. Загрузи скилл `git-release` и следуй ему пошагово.
2. Собери изменения после последнего тега. Тегов в репозитории может не быть —
   тогда бери всю историю.
3. Сгруппируй изменения: Features / Fixes / Chores. Сгенерированные файлы
   (`contracts/dist/`, `frontend/src/api/schema.d.ts`,
   `backend/src/Meetly.Contracts/Generated/`) в changelog не упоминай.
4. Определи тип версии. Для изменений API используй `oasdiff breaking`,
   а не собственную оценку.
5. Обнови версию во всех четырёх местах и `CHANGELOG.md` в формате
   Keep a Changelog. После правки `contracts/main.tsp` пересобери контракт.
6. Прогони проверки перед коммитом и покажи итог.

Ничего не коммить, не тегируй и не пушь без моего явного подтверждения.
Покажи предлагаемые команды и дождись ответа.
